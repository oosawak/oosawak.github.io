MarkdownCMSには、**GitHub向けの公開版**と、**Cloudflareを使う商用版**があります。\
どちらも、Markdownで書いた記事をもとに、生成済みのデータをWebサイトとして表示する仕組みです。

公開版は、自分で設定し、必要に応じて改造して使うための選択肢です。\
商用版は、サイトのデザインやCloudflareへの導入、日々の更新と保守を含めて提供することを目指しています。

## 違いを一覧で

| 項目 | 公開版 | 商用版 |
| --- | --- | --- |
| 基本の構成 | GitHub Actions・GitHub Pages | Cloudflare R2・Queues・Workers |
| 記事と画像の保存先 | GitHubリポジトリ | R2 |
| 記事を更新する流れ | MarkdownをGitHubへpushし、自動ビルド | 管理用画面や対応ツールからR2へ保存し、自動生成 |
| 記事更新時のGitHub | 使用する | 使用しない |
| ソースコード | MITライセンスで公開 | 商用開発部分は非公開 |
| デザイン・初期設定 | 利用者が設定・調整 | 制作・導入サービスの対象 |
| 今後の開発・保守 | 開発・保守終了の最終版 | 今後の開発対象 |

商用版の料金、提供時期、具体的なサポート範囲は現在準備中です。\
ここで紹介するデザイン制作や運用支援は提供方針であり、契約条件が確定したサービスメニューではありません。

## 公開版：自分で扱える、MITのMarkdownCMS

公開版は、ソースコードを読んで仕組みを確かめ、自分のサイトに合わせて設定したい人に向いています。

記事と画像をGitHubに置き、更新するとGitHub Actionsがサイト用のデータを生成します。\
GitHub Pagesから配信するため、自分でPHPの実行環境や記事用のデータベースを用意する必要はありません。

サイト名や紹介文、配色などを設定し、サンプル記事を自分の記事に置き換えて使えます。\
MITライセンスの条件に従って利用・改変でき、商用利用も可能です。公開版が「商用利用禁止」という意味ではありません。

**公開版は、今後の機能追加、不具合修正、セキュリティ修正を予定していない最終版です。**\
導入後の確認、依存するソフトウェアの更新、必要な修正は、利用する側で行う形になります。

- [公開版のリポジトリ](https://github.com/oosawak/markdown-cms)
- [公開版のサンプルサイト](https://oosawak.github.io/markdown-cms/)
- [MITライセンス](https://github.com/oosawak/markdown-cms/blob/main/LICENSE)

## 商用版：GitHubを触らず更新できるCloudflare版

商用版は、記事と画像をCloudflare R2へ保存します。\
変更を受けてWorkerが記事データを生成し、生成に成功した版をサイトとして配信します。

日々の記事更新で、GitHubへのpushやGitHub Actionsを使う必要はありません。\
認証付きの管理用画面や対応ツールを使って、Markdownと画像を届ける構成です。

現在の管理用画面には、記事・画像の保存、生成状態の確認、再生成、プレビューの機能があります。\
生成途中で失敗した場合は、直前に成功した公開版を維持します。

一方、公開前の承認を伴う下書き管理や、本格的な共同編集は、現時点で備えている機能ではありません。\
商用版も、必要な機能を確認しながら提供内容を整えている段階です。

## GMEMO：原稿や資料を、AIと受け渡す場所

[GMEMO](https://oosawak.github.io/gmemo/)は、Google DriveにMarkdownのメモやファイルを保存する道具です。\
仕様書、原稿、画像、引き継ぎ文書などをまとめ、AIへ対象ファイルのURLを渡して作業を頼む入口として使えます。

利用にはGoogle Driveへの接続が必要です。\
ファイルのURLを知っているだけで、非公開の資料を誰でも読めるわけではありません。

GMEMOは、公開版・商用版を選ぶ前の、資料や原稿の整理にも使えます。\
一方、GMEMOへ保存するとCMSにも自動掲載される、という連携は現時点では用意していません。\
記事に仕上げたMarkdownを、選んだCMSの更新方法で届ける形です。

## R2管理画面：記事をサイトへ届ける場所

Cloudflare版には、**「MarkdownCMS R2 試用 v0.1」**という管理画面があります。\
現在導入している試用環境で利用できる画面で、正式な商用サービスの名称や完成版を示すものではありません。

画面内の[操作ガイド](https://markdown-cms-r2.oosawak.workers.dev/admin#guide)で、保存や確認の手順を読めます。\
管理用キーで認証した後、次の操作ができます。

1. 接続と記事の生成状態を確認する
2. Markdownの記事やWebP画像を、保存場所を指定してR2へ保存する
3. 既存ファイルを確認して更新する
4. 必要に応じてサイトを再生成する
5. 最後に生成が成功したサイトをプレビューする

公開設定のサイトでは、保存後の生成が成功するとサイトに反映されます。\
**「下書きとして保存し、プレビューを見てから公開する」という承認待ちの仕組みではありません。**\
生成済みプレビューも、まだ保存していない原稿を表示するものではなく、最後に生成が成功した版を確認する機能です。

管理画面を開けることと、記事を更新できることは別です。\
更新には管理者が用意したキーが必要で、キーはチャットや原稿へ書かず、管理画面の入力欄で扱います。

GMEMOで資料と原稿を整理し、AIと記事を整え、R2管理画面で保存と生成結果を確認する。\
このように、**資料を受け渡す場所と、サイトを更新する場所を組み合わせて使えます。**

## 商品として提供したいのは、デザインと使い続けられる環境

商用版で提供したいのは、プログラムの設置だけではありません。

- お店や団体の内容に合わせたデザイン制作
- Cloudflareの初期設定とサイトの公開
- 記事や画像を更新するための案内
- 運用支援、保守、必要な機能の追加

「どのファイルをどこに置くか」「何を設定すれば公開できるか」を、利用者が一から調べなくても始められる形にします。\
公開後も、誰が何を担当するかを決めて、使い続けられる環境を整えることを重視します。

具体的な対応範囲や費用は、提供条件として明確にしていく予定です。

## 公開版でも商用版でも、サイトの費用は別に考える

公開版のソースコードはMITで利用できますが、利用する外部サービスに費用がかかる場合があります。

商用版も、デザイン・導入・保守などの費用と、Cloudflareの利用料は別の項目です。\
Cloudflareの利用料は、契約プラン、保存容量、読み書きの回数、Workerの処理量などで変わります。\
無料枠があっても、すべての運用が無条件に無料になるわけではありません。

サービスとして提供する際は、これらの費用を誰が負担するかも含めて案内します。

## どちらを選ぶか

GitHubや設定ファイルを扱い、自分で管理・改造したいなら、公開版を検討できます。\
自分のサイトに合うデザインや、導入・更新・保守の支援を求めるなら、商用版がそのための選択肢になります。

**自分で組み立てられる公開版と、デザインから運用までを支える商用版。**\
どちらも、文章をMarkdownとして持ち、必要な情報を更新できるサイトを作るための仕組みです。
