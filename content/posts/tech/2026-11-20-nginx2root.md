2026年11月18日に、nginx の脆弱性が10件まとめて公表されました。\
そのうち5件は、発見した Xint というチームが「nginx2root」という名前で技術情報を公開しています。\
この記事は、Cloudflare の分析記事 [nginx2root（Zero Wire）](https://radar.cloudflare.com/zero-wire/nginx2root) を読んで、要点をまとめたものです。

## 一番大きいのは HTTP/2 の穴

中心は CVE-2026-123007 です。\
HTTP/2 のフロー制御まわりのメモリ破損で、ログインなしに、nginx のワーカーの権限でコマンドを実行できる可能性があります。\
対象は HTTP/2 を有効にした nginx で、最初の版は 1.9.5 です。\
HTTP/2 が入った 2015年から、ずっと潜んでいた欠陥ということになります。\
Xint は、AWS と GCP と Azure の公開サーバーで実行まで実証したとしています。\
攻撃に使う HTTP/2 の制御フレームは、アクセスログにリクエストとして残りません。\
ログがきれいでも、無事の証明にはならない、という点が厄介です。

## 残りの4件

あとの4件もメモリ破損の類で、それぞれ当たる構成が違います。

- CVE-2026-123633: HTTP/2 で後段へ中継する構成（1.19.7 以降）
- CVE-2026-121810: HTTP/3 で同じく中継する構成（1.25.0 以降）
- CVE-2026-123634: proxy_pass に変数を使う構成のリゾルバまわり
- CVE-2026-113425: メールプロキシまわり

F5 の評価は、深刻なもので CVSS 4.0 で 9.2 です。\
コード実行には ASLR の回避が要る、というのが F5 の説明で、Xint はその回避まで含めて実証したとしています。

## 直し方

修正版は、安定版 1.30.7 とメインライン版 1.31.9 です。\
更新したら、設定の再読み込みではなく、プロセスの再起動まで必要です。\
すぐに更新できない場合は、HTTP/2 を切ることが当面の塞ぎ方になります。\
ディストリビューションのパッケージは、版数が変わらなくても修正が入ることがあるので、パッケージ側の情報で確認する必要があります。

## 今の状況

2026年11月18日時点で、この5件は CISA の KEV（悪用が確認された脆弱性の一覧）には載っていません。\
実際の悪用の報告も、まだありません。\
日本でも、国家サイバー統括室から注意喚起が出ています。\
Cloudflare は、自社のエッジ（nginx を大きく改造したフォーク）が公表前に全世界で修正済みだと明言しています。\
Cloudflare のプロキシの内側にあるサーバーは、その間も守られる形です。

## 私の側の話

私の環境には nginx がありません。\
自宅サーバーと Mac の棚卸しに、nginx は載っていませんでした。\
公開は GitHub Pages と Cloudflare に任せていて、配信サーバーを自分で持っていないからです。\
今回の件で差が付くのは、「自分で nginx を立てているかどうか」と「棚卸しができていて、対象かどうかすぐ言えるかどうか」だと思います。\
2015年からの穴というのは、裏を返せば、長く動かし続けてきたサーバーほど対象になる、ということです。\
動かし続けるなら、棚卸しと照合の仕組みが要ります。

## Cloudflare の情報の出し方

この分析記事には、Cloudflare 自身の状況も書いてあります。\
自社のエッジが対象のコードを含んでいて、公表前に直し終えた、というところまでです。\
まずい部分も含めて、直し方と一緒にすぐに出してくれる事業者は、そう多くありません。\
私はこういう情報の出し方をする仕組みは信頼できると思っていて、これからも使っていきたいです。
