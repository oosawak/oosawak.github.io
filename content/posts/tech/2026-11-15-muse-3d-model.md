ミューズさんの3Dモデルを、自宅サーバーで作りました。\
夏版と、漫画に出てくる冬毛版の2体です。\
作るだけではなく、ボーンを入れて、ダンスのモーションで動かすところまで進みました。\
出来た GLB は、[ミューズさんの3Dモデル配布ページ](https://oosawak.github.io/materials/muse-3d/)からダウンロードできるようにしました。

## 環境

生成に使ったのは、自宅の i9 機です。\
Core i9-12900K に RTX 3090（VRAM 24GB）、メモリ 128GB の Ubuntu 機です。\
画像から3Dモデルを作る trellis.cpp の CUDA 版を入れてあります。\
重みは約16.5GB で、コマンドラインからそのまま生成できます。\
サーバーとして常駐させる必要はありません。

前は同じことを、月額課金のサービスで試していました。\
自宅で1体あたり数分で出るようになると、課金してまで使う理由は薄くなります。

## 指示書で回す

私はこのサーバーを直接触っていません。\
ミューズさんが指示書を Markdown で書き、GitHub のリポジトリに置きます。\
i9 側の Codex がその指示書を読んで実行し、報告を Markdown で返します。\
ミューズさんが公開側を確認して、台帳に登録するところまでが一巡です。

やり取りは全部 GitHub 上の文章です。\
指示書には、入力の置き場所、生成の条件、検証のやり方、報告に入れる項目まで書いてあります。\
今回の生成条件は、解像度1024、seed 42 で統一しました。\
夏版は約156秒、冬毛版は約237秒でした。\
VRAM のピークは約5GB で、24GB のカードには余裕があります。\
GLB は夏版が約11.9MB、冬毛版が約16.0MB で、どちらもボーンなし、テクスチャ付きです。

![生成した夏版の正面。クリーム色のフード頭で、大きな青い目がある](tech/muse-3d-summer-front.png)

## 入力画像で決まる

trellis.cpp は単一画像の入力です。\
三面図をそのまま入れると崩れるので、正面の絵を1枚用意します。

ここで一度失敗しました。\
冬毛版の最初の絵は、参考にした漫画のコマが縦長だったことに引きずられて、縦長の画面になりました。\
両腕が画面の端で見切れていて、そのまま生成に回すと腕の先が欠ける絵です。\
横長の画面で、全身と両腕が余白を持って収まる構図に直しました。

冬毛のデザインは、縦スクロール漫画「ふゆげミューズ」に出てくる姿が正本です。\
白く長い毛束の冬毛に、大きな青い目、頭の両側の小さな丸い耳です。\
体型のバランスと、体の前側の毛並みの流れが合うまで、絵は3回作り直しました。

![生成した冬毛版の正面。白く長い毛束に包まれて、頭の両側に小さな丸い耳がある](tech/muse-3d-winter-front.png)

## ボーンを入れる

生成した GLB にはボーンが入っていません。\
動かすには、関節とウェイトを付けるリギングが要ります。\
これも指示書で i9 に頼みました。\
使ったのは UniRig という自動リギングの道具です。

UniRig の処理は、骨格の推定、スキニング、元のモデルへの結合の3段階です。\
初回は重みの取得も含めて、骨格に約147秒、スキニングに約384秒、結合に約24秒かかりました。\
結果、28関節のリグが付きました。

ところが、確認で問題が出ました。\
腕の骨を15度回すテストをすると、同じ側の目が崩れたのです。\
頭の頂点に、腕の骨のウェイトが混ざっていました。\
自動で付いたリグは、そのままでは使えませんでした。

![腕を15度回したテストの画像。上げた腕と同じ側の目が、引かれて崩れている](tech/muse-3d-arm15-broken.png)

## リグの調整

調整も、指示書をもう1枚書いて頼みました。\
内容は3つです。\
過剰に分かれていた手先の関節を合算して、28関節から22関節にしました。\
頭部の頂点から腕と脚のウェイトを取り除き、頭と首へ寄せました。\
関節の名前を、VRM のヒューマノイドの名前に揃えました。

同じテストをやり直すと、頭部の頂点の変位は 0.0 で、目は崩れなくなりました。\
数値で確認できる形にしてあるので、直ったかどうかが文面で判断できます。

![調整後の同じテスト。腕を15度回しても、目は崩れていない](tech/muse-3d-arm15-fixed.png)

次に、CC0 で公開されているダンスのモーションを当ててみました。\
目と口は保たれました。\
ただし、頬が横に帯状に伸びて、フードの側面が板状に伸びて、肩と首元の毛が引き伸ばされました。\
静止画では分からない問題は、動かして初めて出ます。

![ダンスモーションを当てた画像。頬が横に帯状に伸びている](tech/muse-3d-dance-before.png)

## Blender の Python で直す

この調整は、Blender の画面を開いて手で直したわけではありません。\
Blender の Python（bpy）のスクリプトで、GLB を読み込んで、ウェイトを数値で書き換えて、書き出すところまでを回しています。\
頭部の変位 0.0 のような合否の数値も、確認画像の描画も、同じスクリプトの仕事です。

だから、指示書に「何をどう直すか」と「合否の基準」を書けば、実行と検証がそのまま回ります。\
人の手番は、報告の画像と数値を見て、次に進めるかを判断するところに寄りました。

小さな癖もありました。\
bpy は、書き出しが終わったあとに、終了時のエラーで落ちることがあります。\
出力ファイルと検証結果が揃っているかを確認してから、次へ進めました。

## 顔は後付けにする

公開してから気づいたのは、冬毛版の目です。\
テクスチャに焼き込まれた目の輪郭が強く出て、ちょっと怖い顔になりました。\
このキャラクターは元の絵が平たいタッチなので、顔のパーツは平らな部品で後から付ける方が合うはずです。

そこで、目も口も描いていない、顔が無地の土台を、夏版と冬毛版の両方で作りました。\
顔に凹凸は出ませんでした。

![顔が無地の夏版。目も口もなく、顔はツルッとした面になっている](tech/muse-3d-blankface.png)
\
口パクも、この無地の顔に口のパーツを載せる路線で考えています。

無地の顔のモデルにも、ボーンが入りました。\
ただし関節は16本で、顔あり版にある肩や胸の骨がありません。\
踊らせてみると、顔の下端がくちばしのように大きく伸びました。\
顔が無地でも、変形の問題は解けないことが分かりました。\
今のモデルの VRM 化は、i9 に依頼しているところです。\
胸や首元の調整をもう1回やる案もありましたが、こだわり過ぎない判断で取り下げました。

## 文章だけで回った

当初の見立てでは、リギングは Blender で自分の手でやるつもりでした。\
実際には、生成も、リグの組み込みも、調整も、全部が文章のやり取りで回りました。\
検証のやり方と合否の数値まで指示書に書いておくと、手を動かす部分まで任せられます。\
道具を「AIに使ってもらう」形にしておくと、こういう制作も回る、というのが今回の収穫です。
