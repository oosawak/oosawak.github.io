2026年11月19日に、PHP のセキュリティ修正が出ました。\
修正版は 8.2.36 と 8.3.37 と 8.4.28 と 8.5.13 で、同日に出た 8.6.0 にも修正が含まれています。\
この記事は、Cloudflare の分析記事 [phpAfterShell and six other PHP critical flaws（Zero Wire）](https://radar.cloudflare.com/zero-wire/php-november-2026-security-release-phpaftershell) を読んで、要点をまとめたものです。

## 中身

直った脆弱性は17件で、そのうち7件が Critical（CVSS 4.0 で 9.2）です。\
PHP 公式の事前告知では、Critical のものは「デフォルト以外の設定、または珍しい構成」でのみ影響する、とされていました。

## phpAfterShell

名前が付いたのが CVE-2026-126714、通称 phpAfterShell です。\
PHP のデフォルトのファイルベースのセッションハンドラにあります。\
セッションの書き込みが途中で止まると、新しいセッションの先頭と古いセッションの末尾が混ざったファイルが残ることがあります。\
次のアクセスで、その混ざった内容が読み込まれて、置かれたオブジェクトが復元される、という筋です。\
発見した depthfirst は、別のメモリ破損と組み合わせてコード実行まで行ったとしています。

## もう1つの大きなもの

CVE-2026-129289 は、PHP-FPM へのリクエスト・スマグリングです。\
ログインなしに、2つ目の FastCGI リクエストを紛れ込ませて、ワーカーの権限で PHP コードを実行できる可能性があります。\
当たるのは、前段のサーバーが後段への接続を使い回す設定のときで、nginx の fastcgi_keep_conn などが例に挙がっています。\
接続を毎回閉じる前段は、対象になりません。

## 10月の続きでもある

10月に緊急修正が出た php2shell（CVE-2026-109618 と CVE-2026-109619）を覚えている方もいると思います。\
今回の7件の中には、その10月の修正の不完全だった部分を閉じるものが2件入っています。\
セッションのシリアライザの不一致（CVE-2026-115560）も、今回で正式に直りました。\
この修正で、セッションのアップロード進捗はデフォルトでオフになります。\
PHP の大きな修正は、10月に続いて2か月連続になりました。

## 今の状況

2026年11月19日時点で、この17件はどれも KEV には載っていません。\
実際の悪用の報告もありません。\
直し方は、使っている系列の修正版へ上げて、ワーカーを再起動することです。\
上げた後も、設定ファイル側でセッションのアップロード進捗を明示的にオンにしていると、その設定が優先されるので、確認が要ります。\
PHP 8.1 以前はサポートが終わっていて、公式の修正は出ません。

## 私の側の話

私の環境では PHP を動かしていません。\
公開側は静的に生成した HTML を配信する形で、サーバーでプログラムを動かし続けない設計にしています。\
10月の件のときも書きましたが、今回も同じ感想です。\
直す対象を持たないことは、それ自体が防御になっています。\
サーバーで PHP を動かしている側は、nginx の件と重なって、今週はかなり忙しいはずです。

## Cloudflare の情報の出し方

この分析記事は、脆弱性の中身だけでなく、何を確認して、どう直すかまで、手順の形で書いてあります。\
読む側がそのまま自分の環境の点検に使える情報です。\
こういう情報を、件が起きた直後にしっかり出してくれる事業者は、そう多くありません。\
私はこういう情報の出し方をする仕組みは信頼できると思っていて、これからも使っていきたいです。
