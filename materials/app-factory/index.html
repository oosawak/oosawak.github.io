DEDICATED APPS

一枚のHTMLから、アプリができる。

画面の設計を AIエージェントのミューズさんに頼んで、一枚の HTML で作ってもらいます。それをツールへドラッグアンドドロップすると、Android のパッケージが出来上がります。

流れ

  1. 画面を頼みます。たとえば「カーナビと、音楽を流す機能」のような画面を、ミューズさんが一枚の HTML で作ります。
  2. その HTML を、ツールへドラッグアンドドロップします。
  3. ツールが殻と組み合わせて、ビルドと署名をします。
  4. Android のパッケージが出てきます。入れる人は、それを電話に入れるだけです。

構成図

土台は「どこでもソース管理」

このツールのベースは「どこでもソース管理」です。その中には Hako@Linux と同じ仕組み（箱と入り口）が入っています。ミューズさんはその仕組みを理解して HTML を書くので、出来上がるアプリには、箱リナックスとの通信処理が最初から入っています。

中の作り

画面は一枚の HTML

作る人が触るのは、画面の HTML だけです。表示は WebView で映し、操作は箱側へ返ります。表示と操作の、双方向です。

仕事は箱の中

記録や処理は、箱の中の Python がやります。センサーや位置を読む橋は、もう動いているものを使います。Bluetooth のセンサーを取り込む橋も、同じ形で足せます。

肝は橋の約束事

箱との通信の決まりを仕様として固定してあります。だから、AI が書く HTML はどれも、箱と話せます。

なぜ分けるのか

1つの大きなアプリに全部を入れるのではなく、用途ごとの小さい専用アプリに分けます。権限も機能も、その用途に要るものだけに絞れます。画面は作り直しが軽いので、専用の UI を作り込むメーカーの作り方とは逆に、画面を使い捨てにできます。残る価値は、箱の中の記録と処理です。

実例

壁紙アプリ

放り込むとアプリになる流れは、壁紙アプリで先に実証済みです。この仕組みの原型です。

バスの位置情報

電話1台でバスロケをする仕組みを、この作り方で作ります。紹介ページと、GPS ログの地図表示の試作があります。

クマの出没情報

出没したら写真と位置を送り、集まった記録から予測と個体の管理をする仕組みを、この作り方で作ります。

箱をコアにしたナビ

ナビのコアに箱リナックスを置き、ドライブレコーダーの情報も一緒に表示する形を、この作り方で作ります。

部品ごとの実証は済んでいます（箱、センサーの橋、放り込むとアプリになる流れ）。一枚 HTML から包む部分と、Bluetooth の橋は、これから作ります。
