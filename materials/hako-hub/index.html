hako（箱）のカタログ

Hako Hub

箱の中身のカタログです。Docker Hub のように巨大なイメージを置くのではなく、数KBのレシピ（設定ファイル）を置きます。 VS Code や Forgejo のようなソフトは箱に同梱せず、ここからレシピを取って、その場で入れる形です。 人がブラウザで読むカタログと、hako コマンドが読む定義は、同じものを使います。

hako は独立した土台です。土台とレシピの仕組みだけを用意しておき、その上に用途ごとの構成を載せます。ソース管理の道具一式を載せた構成は、その一例です。

土台（セットアップで選ぶ中身）

箱の中身は、セットアップの時に選べます。複数入れて切り替えることも、同時に動かすこともできます。作業場所は箱ごと、共有したいデータは共通の共有領域に置く形です。

実機実証済み

Alpine 3.24

超軽量・速さ特化の土台。軽いサーバーを常駐させる向けです。

土台 3.84 MiB ／ 展開 0.51 秒 ／ git・nginx・Python を入れても 69.5 MiB ／ セットアップ約11秒（Pixel 3a 実測）

現行の標準

Ubuntu 24.04

互換性・全部入り特化の土台。code-server や VS Code からの接続など、glibc が要るソフトはこちらで動かします。

土台 約643 MiB（Pixel 3a 実測）

候補

Ubuntu 26.04

パソコン版の箱と版を揃えるための候補。公式の土台ファイルの存在は確認済みです。

後回し

Debian

Ubuntu と役割が重なるため、今は入れていません。必要になった時に追加します。

レシピ（Hub から取って入れるソフト）

レシピには2つの型があります。apt 型は土台のパッケージから入れ、release 型は公式の配布ファイルを取得して、ハッシュ（SHA-256）で確かめてから入れます。

hako up（compose の定義から）

箱に最初から入っている物

入り口と制御だけは、最初から入っています。SSH は「箱に入るための入り口」なので、後から入れる形にはできません。

ネイティブ同梱

OpenSSH（sshd）

箱への入り口。Android ネイティブで直接動きます。proot と合わせてもメモリは約6.5 MiB（Pixel 3a 実測）。

ネイティブ同梱

Rust 制御コア ／ git ／ 基本コマンド

サービスの起動と停止、状態の確認を担う中心と、作業の基本道具。アプリ本体の待機メモリは 37.9 MiB（Pixel 3a 実測）です。

使い方

  • hako list ― 使えるレシピと、導入の状態の一覧
  • hako up 名前 ― 未導入ならレシピに沿って自動で入れて、起動する
  • hako ps ― 稼働中のサービスの一覧
  • hako down 名前 ― 停止する（データは残る）
  • hako remove 名前 ― 作業場所ごと片付ける

安全のための線引き

箱の中では、個別のパッケージを足す操作（apt install）は自由です。一方、土台をまとめて新しくする操作（apt upgrade）は、案内を出して止める仕組みが入っています。 proot の変換の仕組みと新しいライブラリが合わず、箱が動かなくなるのを防ぐためです。土台を上げる時は、新しい土台（rootfs）に差し替える形で行います。
