「箱」の考え方

Hako@Linux は、Linux そのものではなく「箱」を作る仕組みです。

中身を替えても、入口が残る

箱の中の Linux（土台）を切り替えても、SSH の入口はホスト側に残ります。接続中の作業は切れず、新しい接続だけ新しい土台へ入ります。

複製して、捨てられる

箱の複製とスナップショットは約5ミリ秒。試して、壊れたら、巻き戻す。実験用の箱を気軽に作って、気軽に捨てられます。

人にも、AI にも渡せる

ターミナルとブラウザとファイルを、そのまま渡せる作業場です。AI エージェントに仕事を任せるための場所として作っています。

本体は軽いまま

基本機能は軽く保ち、必要な道具は後から足します。土台やソフトを同梱せず、レシピから組み立てるのが Hako@Linux のやり方です。

できること

基盤初版（v0.1）で、実機で確認したことです。

約1秒でデスクトップ

起動から約1秒で、Wayland デスクトップ（labwc）が使えます。待ち時間の無い Linux が、Mac の中に常駐します。

音が出る

音声は virtio-snd から Mac の CoreAudio へ出ます。Firefox で YouTube の音も再生できます。

Mac の日本語入力が届く

Mac 側の日本語入力（IME）が、そのまま箱の中のアプリへ届きます。届くまでの往復は実測で約66ミリ秒です。

メモリ2GBでも動く

メモリ2GBの設定で、Firefox と YouTube の再生を確認しました。解像度（1024×768〜1920×1080）とメモリ・CPU（2コア/2GB〜6コア/12GB）は、メニューで切り替えられます。

Mac とファイル共有

共有フォルダ（~/Mac）が、箱の中から読み書きできます。Mac と箱の間で、ファイルをそのままやり取りできます。

hako install

GitHub CLI や Codex などの道具は、hako install で必要な時に足せます。本体は軽いままです。

機能一覧

基盤初版（v0.1）に入っているものです。

箱の基本

土台は Ubuntu 24.04 系で、デスクトップは Wayland（labwc）です。ディスクは 16GB（空き約9.3GB）。アプリの名前は Hako@Linux.app です。

入り口

Rust 製の SSH サーバー（russh）がホスト側に常駐します。接続は実測 0.0311 秒。土台を切り替えても再起動せず、接続中のセッションは維持されます。

箱の管理

APFS の Copy-on-Write を使った複製・スナップショット・切り替えと巻き戻し。巻き戻しの前には、自動で退避が作られます。

見た目の切り替え

Hako Look で、テーマとフォント（12/18/24pt）が切り替えられます。ステータスバーには解像度と CPU・メモリの使用量が出ます。

道具の追加

hako list / hako install で、道具をオンデマンドで導入できます。基本機能は軽く保ち、要る物だけを足す形です。

仕組み（技術者向け）

土台は libkrun と Hypervisor.framework です。Apple Silicon の Mac 上で Linux の仮想マシンを動かし、ゲストは Ubuntu 24.04 系に labwc（Wayland）を載せています。表示は virtio-gpu の直接表示です。

入口はホスト側に常駐します。Rust の russh で作った SSH サーバーが土台の外側にいて、土台を切り替えても接続が残ります。通信は gvproxy で、日本語入力の直通しもこの経路で約66ミリ秒まで詰めました。

Android 版の仕組みと実測は Android 版のページ にあります。コミュニティは r/hakolinux です。

今の制限

正直に書いておきます。

描画はソフトウェア2D

表示の描画はソフトウェア2D（pixman）で、3D ハードウェア加速はありません。YouTube の再生はできますが、重い3D用途には向きません。

解像度は起動時に選ぶ

解像度は起動時の設定で決まります。窓の大きさを変えても、ゲストの解像度は自動では追随しません。

まだ基盤初版です

これは基盤初版（v0.1）です。AI 特化型と教育型のディストリビューションは、この土台の上にこれから作ります。内容は変わることがあります。
