どこでもソース管理

SOURCE CONTROL ANYWHERE

アプリを1つ起動するだけ。
ソースの置き場と、編集画面と、公開プレビューが、自分の機械の中にそろいます。
ネットが無くても動きます。

これは何か

GitHub のような「ソースコードの置き場」を、クラウドではなく自分のパソコンの中で動かすアプリです。アカウント登録も、サーバーの用意も要りません。アプリの中に小さな Linux の箱が入っていて、その中で置き場と編集画面が動きます。

アプリの中身
箱（Ubuntu） ― 起動すると中で動くもの
・Forgejo ― ソースの置き場（GitHub の役割）
・VS Code Server ― ブラウザで開く編集画面。ターミナル付き
・Pages ― 作ったサイトをその場で表示する仕組み
・Node／Python／Rust ― もの作りの道具
・壁紙 ― 箱が動いていることを見せる「顔」
データ（箱とは別） ― 利用者のもの全部
リポジトリ、ホームフォルダ、ソースコード、データベースのデータ。
箱は作り直せます。守るのはこのデータだけです。

できること

起動するだけ

環境構築がありません。アプリを開けば、置き場と編集画面がもう使えます。教える側が用意するのはアプリ1個だけです。

ネットなしで完結

教室、ネットに繋げない役場の現場、船の上、災害時。ネットが無い場所でも、作る・置く・見るが全部できます。

USB 1本で持ち運ぶ

パッケージには Windows 版と Mac 版を同梱し、データは OS から独立させてあります。どちらの機械に挿しても、同じ置き場が開きます。

バックアップはコピーだけ

データは1つにまとまっているので、コピーすればバックアップ完了です。箱の側は作り直せます。アプリを閉じる時に、パソコン側へ自動で控えを取る形も設計中です。

AI の作業場に

ミューズさんのような AI が、作業の置き場として使えます。人と AI が、同じ置き場を見て一緒に作業できます。

更新は承認してから

勝手に更新しません。棚卸しをして、脆弱性と照合して、報告が出て、承認してから更新します。ネットが無い場所へは、更新パッケージを持ち込めます。

壊しても戻せる

箱の中は本物の Linux です。学習や実験で壊しても、箱を作り直せば元通り。データは無事です。

VS Code と一緒に

普段の道具は VS Code のままで大丈夫です。置き場と実行環境だけ、箱が引き受けます。VS Code の無い機械では、ブラウザの編集画面も使えます。

いつもの VS Code からつなぐ

普段の VS Code がメインの道具なら、そのまま箱につないで使えます。やり方は、いつものリモート接続と同じです。

1. 左下から接続

VS Code の左下にあるリモートのボタンから「ホストに接続」を選びます。

2. 箱のアドレスを入れる

このツールのアドレスを入れると、VS Code が箱の中につながります。

3. すぐ作業

フォルダを開いて、下のターミナルでそのまま作業が始められます。ファイルは箱の中、置き場も箱の中です。

実測（試行構成）

項目数字
起動（3つのサービスが使えるまで）中央値 約12.4秒
git の push初回 約0.79秒／差分 約0.41秒
箱の大きさ（全部載せ）6.61GB（圧縮すると 2.63GB）
初回導入（まっさらな状態から）約114秒

※ 全部載せ構成（Ubuntu の箱に Forgejo、編集画面、Pages、Node／Python／Rust、壁紙生成まで入れた状態）での実測です。Mac／HVF、2026-11-23 計測。

実測の詳細

測定環境MacBook Pro（M1 Max、RAM 64GB、macOS 26.7.3）／ QEMU 11.1.3＋HVF（CPU host、2 vCPU、メモリ 4096MiB）／ ゲストは Ubuntu 26.04.1 LTS Minimal arm64（glibc 2.43）
部品の版数Forgejo 15.0.11 ／ code-server 4.146.0（公式 standalone）／ Caddy 2.6.2 ／ Node 24.22.3（npm 11.19.1）／ Python 3.14.4 ／ Rust・cargo 1.96.1
起動の内訳Tauri の入口→窓のロード通知 中央値 0.34秒 ／ 窓の通知→3サービス（Forgejo、編集画面、Pages）が HTTP 200 を返すまで 12.07秒 ／ 入口→利用可能 12.41秒（3試行: 12.70／12.11／12.41）
push の条件合計 11,509,760 バイト（テキスト100ファイル＋10MiB のバイナリ、4コミット）。HTTP/1.1、ウォームアップ1回を除く3標本。初回相当 0.779／0.785／0.848秒、差分 0.406／0.422／0.410秒
壁紙の生成箱の中での Mac 向けクロスビルド。初回（依存キャッシュなし）217.75秒、再生成 36.52秒。搬出アーカイブ 3,260,427 バイト、ホスト側で署名の厳密検査まで合格
大きさの詳細全部載せの箱 6,613,172,224 バイト ／ 圧縮コピー 2,629,435,392 バイト ／ まっさらな状態から導入した箱 5,463,932,928 バイト
確認の方法編集→push→Pages 表示は、commit の SHA と本文のハッシュの一致で確認。単なる HTTP 応答では合格にしていない

※ 参考: 従来の Alpine 構成は、起動（Tauri→シェル応答）が約24秒、push が初回 0.799秒／差分 0.413秒、データの箱が約7.3GB です。ただし起動の測定地点と構成が違うため、単純な優劣の比較には使えません。

こんな場所で

学校

学生の「相方」として。アカウント登録なしで、git の練習、Linux の学習、プログラミングに使えます。メインの道具は普段の VS Code のままで、生徒の機械にサーバーを用意する必要がありません。

小さな役場・現場

閉じたネットワークの中でも、文書とデータの置き場と公開ができます。

個人の開発

自分のソースを自分の手元に置いて、クラウドに依存しない開発環境として。

災害時

大事なものは USB の中にまとまっています。USB を持って出れば、別の機械でそのまま続きができます。停電でネットやクラウドが使えない時も、手元で完結します。
